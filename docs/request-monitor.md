# Понятный журнал запросов в реальном времени

Монитор читает HTTP-журнал Railway и переводит запросы на русский язык.
Он работает в терминале на компьютере владельца и не меняет приложение или базу.

## Запуск на настроенном компьютере

Дважды откройте `Start-Monitor.cmd` в корне проекта. Или из PowerShell:

```powershell
python -X utf8 scripts/request_monitor.py
```

Переходите по страницам сайта или отправляйте запросы CRM. В терминале появляются
время Asia/Qyzylorda, понятное название действия, объяснение ответа, метод GET/POST,
HTTP-статус и длительность. Успешная загрузка CSS/изображений и healthcheck скрыты;
ошибки таких запросов остаются видимыми. `--all` показывает все эти обращения.
Ctrl+C останавливает только просмотр. При обрыве соединения монитор повторно
подключается, скрывая повторные записи по ID запроса. Если версия CLI возвращает
снимок HTTP-журнала, монитор обновляет его каждые 5 секунд без лишних сообщений.
Доставка записей также зависит от задержки самого Railway; это не трассировка
каждой внутренней операции приложения или SQL-запроса.

Примеры объяснений (иллюстрации формата):

```text
02.11 10:20:00 | УСПЕХ | Создание задачи из CRM
  Что произошло: Задача создана и отправлена отделу; сохранены история и штатные уведомления.
  Технически: POST · HTTP 201 · 48 мс

02.11 10:20:03 | ПОВТОР | Создание задачи из CRM
  Что произошло: Возвращена ранее созданная задача. Повторная задача не создавалась.
  Технически: POST · HTTP 200 · 12 мс
```

Монитор не видит тело формы, API-ответа, личные данные, пароль или Bearer-ключ.
IP, User-Agent, query string и неизвестные пути не выводятся. Длительность запроса
не означает длительность выполнения задачи человеком. По HTTP 302 видно только
перенаправление, а не успешное изменение задачи: HTML-форма могла вернуть ошибку
на следующей странице. Точную причину отказа ищите в форме или JSON-ответе API.
При POST события дедлайна 201 означает обработку; число уведомлений может быть
нулевым из-за дедупликации или отсутствия доступных получателей.

## Другой компьютер

Нужны Python 3.10+, данные часовых поясов (`pip install tzdata` на Windows),
официальный Railway CLI (`npm install -g @railway/cli`) и вход `railway login`.
У аккаунта должен быть доступ к проекту. Ключи CRM для просмотра журнала не нужны.

Для первого запуска укажите проект и сервис:

```powershell
python -X utf8 scripts/request_monitor.py --project YOUR_PROJECT_ID --service caspian-college
```

Если CLI не находится автоматически, добавьте `--railway "C:\path\to\railway.exe"`.
При npm-установке на Windows монитор сам ищет родной executable рядом с `.cmd`.
Для постоянных параметров создайте `%USERPROFILE%\.caspian-college-monitor\config.json`:

```json
{
  "project": "YOUR_PROJECT_ID",
  "service": "caspian-college",
  "environment": "production",
  "railway": "C:/path/to/railway.exe"
}
```

Поле `railway` необязательно, если CLI доступен через PATH. Не сохраняйте в этом
файле ключи API и пароли. Настройки и авторизация Railway остаются вне Git.

Последние 20 записей без непрерывного ожидания:

```powershell
python -X utf8 scripts/request_monitor.py --once --lines 20
```

При отсутствии новых обращений журнал спокойно ожидает. На Railway Free приложение
может засыпать или быть остановлено после исчерпания кредитов — монитор не меняет
эти ограничения. Для отслеживания обращений компьютер и монитор должны быть включены.
